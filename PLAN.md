# X3M Slack translation bot

## Goal and pilot scope

Give X3M support agents a private way to understand customer messages and send reviewed replies in the customer’s language. Pilot with X3M staff in approved Slack Connect channels. Customers keep using Slack normally and see replies posted by **X3M Translate**, with the approving agent’s name in the reply.

| Translate for Slack capability | X3M delivery |
|---|---|
| **Free** includes message shortcuts, slash commands, and a translation form. | Ship a private message shortcut and a composer command that opens a translation form. |
| **Pro** adds publishing and automatic translation rules for individuals or channels. | Ship publishing after human review. Use automatic language detection to populate a private support queue. |
| **Plus** adds two-language automatic translation. | Support a primary language and additional reply languages per channel, with several preferred languages per user. Keep automatic public translation, user-message replacement, and DM translation outside the pilot. |

Source for the reference capabilities. [Translate for Slack plans](https://docs.translate.technology/plans-and-pricing/plans)

## Slack experience

1. **Set personal languages.** In App Home, agents choose an ordered list of languages they can read. Start with English. The first language is the default translation target. Agents can reorder or replace the list. Include English, Spanish, Korean, Vietnamese, Traditional Chinese for Hong Kong, Simplified Chinese, Japanese, Thai, and Indonesian in the pilot language selector. Offer written Cantonese as a separate target after a Hong Kong reviewer validates it. Slack App Home is private to each user. [Slack App Home](https://docs.slack.dev/surfaces/app-home/)

2. **Set up a channel.** When an X3M admin invites the bot to a channel, show it as pending in the admin’s App Home. The admin enables local observation. Use the latest 50 confidently classified human messages from the previous seven days, collected after opt-in. Suggest the most common language once there are at least 20 samples and it accounts for at least 60%. Show the sample count and language breakdown. The admin confirms the primary language, adds any secondary reply languages, and separately enables provider translation and bot posting. If there is too little evidence, let the admin set the languages directly. [Slack message events](https://docs.slack.dev/reference/events/message/), [Slack channel membership events](https://docs.slack.dev/reference/events/member_joined_channel/)

3. **Read a customer message privately.** App Home lists recent messages whose detected language is outside the agent’s preferences. Each row shows the channel, time, detected language, and **Open original** link. The agent uses **Translate privately** from the original message’s menu. Open a private modal with a preferred target preselected and let the agent switch targets. Keep the shortcut available for eligible messages with mixed or uncertain language, even when they have no queue entry. Slack provides the posted message in the shortcut payload. The pilot uses that payload for translation and uses permalinks for queue navigation. [Slack shortcut payloads](https://docs.slack.dev/reference/interaction-payloads/shortcuts-interaction-payload/), [Slack message permalinks](https://docs.slack.dev/reference/methods/chat.getPermalink/)

4. **Draft, review, and send.** Use `/x3m-translate` in the channel composer for a new message, or **Draft translated reply** on a customer message for a threaded response. Enter the draft in a private modal. Default to the channel’s primary language. For a threaded reply, preselect the detected customer language when it matches a configured target. The preview shows the editable translation, target language, destination, and bot attribution. **Send to Slack** posts only the reviewed text with the approved agent display label. Use the root message timestamp for thread replies. If the thread is unavailable, show the failure in private and keep the draft available for copying. Slack’s composer shortcuts launch app interactions without access to unsent composer text, and custom slash commands have no thread invocation. [Slack shortcuts](https://docs.slack.dev/interactivity/implementing-shortcuts/), [Slack slash commands](https://docs.slack.dev/interactivity/implementing-slash-commands/), [Slack `chat.postMessage`](https://docs.slack.dev/reference/methods/chat.postMessage/)

Only authorized X3M agents use these controls. External Slack Connect members can write customer messages and read approved bot replies in their shared channels. Slack restricts shortcuts and slash commands to the workspace that installed the app. [Slack Connect developer guide](https://docs.slack.dev/apis/slack-connect/)

## Implementation in four increments

The workspace is empty. Start with a Python service using Slack Bolt, a versioned Slack manifest, SQLite migrations, and one Docker container with a persistent volume on X3M-approved infrastructure. Use separate Slack apps, databases, and secrets for sandbox and pilot. Use Socket Mode for the single-workspace install. [Local workspace](/Users/federico.ocampo/Development/tools/slack-translations-bot), [Slack Bolt for Python](https://github.com/slackapi/bolt-python), [Slack Socket Mode](https://docs.slack.dev/apis/events-api/using-socket-mode/)

### 1. Prove the Slack and Claude paths

- Install the sandbox manifest with App Home, interactivity, message shortcuts, the composer command, and public and private channel events. Start with bot scopes `commands`, `chat:write`, `channels:read`, `channels:history`, `groups:read`, and `groups:history`, plus an app token with `connections:write`. Use Slack IDs in a deployment-managed agent and admin allowlist. Keep separate roles and require current channel membership for the user and bot.
- Open a loading modal and acknowledge within Slack’s three-second window. Check permissions and call the provider outside that window. Update the modal using its current view revision. Use `chat.postMessage` with the fixed bot identity, link unfurls off, and thread broadcast off. Prove both paths in a sandbox shared with a second workspace before building the queue. [Slack interaction handling](https://docs.slack.dev/interactivity/handling-user-interaction/), [Slack modals](https://docs.slack.dev/surfaces/modals/), [Slack `chat.postMessage`](https://docs.slack.dev/reference/methods/chat.postMessage/)
- Call Anthropic directly with the OpenAI Python client, `base_url=https://api.anthropic.com/v1/`, and `chat.completions.create`. Keep the base URL, API key, and exact Claude model ID in deployment configuration. Expose one internal interface, `translate(text, source_language, target_locale, glossary) -> TranslationResult`. Send one system instruction and one text input. Validate the returned text, finish reason, and protected placeholders before rendering. Add contract tests for malformed, empty, truncated, timed-out, and rate-limited responses. Run a synthetic smoke test against the configured Claude model before pilot activation. [Anthropic OpenAI SDK compatibility](https://platform.claude.com/docs/en/cli-sdks-libraries/libraries/openai-sdk)

### 2. Add channel setup, detection, and App Home

- Persist preferences, channel policy, detection metadata, queue dismissals, and send receipts. Scope all records by workspace. Identify Slack messages by channel ID and message timestamp. Store the thread root and message revision where available. Consume new events only. Deduplicate Slack event IDs and upsert by message revision. Reclassify edits and remove deleted messages. On bot removal or a Slack Connect channel ID change, suspend the channel, clear its pending previews and queue links, and require admin reapproval. [Slack Events API](https://docs.slack.dev/apis/events-api/), [Slack channel ID change](https://docs.slack.dev/reference/events/channel_id_changed/)
- Run Lingua locally. Strip Slack markup, URLs, code blocks, identifiers, and emoji from the classification input. Skip bot messages, service events, and messages with no usable text. Require both a confidence floor and a margin over the second candidate. Tune thresholds on labeled support examples. Classify uncertain, short, and mixed text separately so it cannot skew channel suggestions. Keep detected language separate from reply locale. A Chinese detection does not determine the customer’s preferred script or Cantonese usage. Background processing makes zero LLM calls. [Lingua language detector documentation](https://github.com/pemistahl/lingua-py)
- Show the 20 newest undismissed matches from the last seven days in each agent’s private queue. Refresh on App Home open and on demand. Recheck membership before rendering channel rows and before every provider call or send. Remove rows after a membership loss, deletion, or policy disablement. Queue entries contain metadata and links only. Keep observed message bodies and draft text out of the database and logs. [Slack App Home](https://docs.slack.dev/surfaces/app-home/), [Slack `conversations.members`](https://docs.slack.dev/reference/methods/conversations.members/)

### 3. Add translation quality controls and safe sending

- Ship a versioned X3M glossary for product names, error codes, and support terms. Mask sensitive patterns and protect URLs, code, mentions, numeric values, and identifiers with local placeholders. Restore permitted placeholders after validation and keep secrets redacted. Render model output as inert text, with mention expansion and unfurls disabled. The translation prompt treats message content as data and preserves meaning, tone, uncertainty, and commitments. Pass only the selected text and applicable glossary entries to Claude.
- Keep raw text, preview edits, and any translation reuse in process memory for up to 15 minutes. Scope preview state to the agent and bind it to the channel, thread, target, and revision. Require a new review if the destination or target changes. If the process restarts or the preview expires, ask the agent to regenerate it. Disable provider calls when the channel, workspace, or deployment flag is off.
- Claim a durable send receipt before calling Slack. A second click on the same preview returns its existing status. Recheck role, membership, destination, policy, and preview revision immediately before dispatch. Record Slack’s returned timestamp and link on success. On an ambiguous timeout or crash after dispatch begins, mark the result **Delivery unknown** and direct the agent to check the thread. Retry only when Slack explicitly indicates that it did not accept the post. A stale thread never becomes a new channel post. [Slack `chat.postMessage`](https://docs.slack.dev/reference/methods/chat.postMessage/), [Slack Web API rate limits](https://docs.slack.dev/apis/web-api/rate-limits/)

### 4. Launch a bounded support pilot

- Run synthetic traffic in a normal channel, a private channel, and a two-workspace Slack Connect channel. Before enabling real customer text, record X3M’s approval of eligible channels, account-specific provider retention terms, redaction policy, and customer disclosure. Anthropic’s published standard API retention is up to 30 days, with documented exceptions. Application TTLs apply only to X3M’s service. [Anthropic API data retention](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organizations-data)
- Start with one approved Slack Connect channel. Expand to up to three once support and security owners review the pilot evidence. Use a default application-side translation budget of **$25 per month** during the pilot. Reserve estimated cost before dispatch using configured model prices and conservative token bounds, then reconcile reported usage. Keep reservations for ambiguous provider calls and stop admitting requests at the limit. Track token usage, preview latency, detector abstentions, API errors, send outcomes, and privacy-safe feedback. Set separate controls to pause detection, provider calls, and bot sends.
- After the pilot, add **local-language support intake** for issue type, impact, affected app version, and time zone. Then add **APAC handoff briefs** that link to original messages and extract unresolved questions for the next support shift. Add an optional local-language acknowledgment that an agent reviews before sending. Sequence these behind the glossary and feedback work so reviewers can identify which issues come from terminology, translation, or missing context.

## Acceptance and rollout gates

| Gate | Pass condition |
|---|---|
| **Slack end to end** | Capture sandbox evidence for ten cases. Cover baseline before install, saved preferences, channel suggestion and override, two-agent queue isolation, private translation of a thread reply, composer draft, external receipt in the correct thread, revoked membership, edits or deletion, and duplicate or ambiguous sends. Use a second workspace to verify customer visibility. |
| **Language detection** | Use at least 240 labeled synthetic or approved de-identified examples. Include Korean, Vietnamese, Hong Kong Traditional Chinese, English, Spanish, and mixed or ambiguous text. Require at least 95% precision among messages the bot confidently labels. Report recall, abstention, and per-language counts separately. If a language misses the precision gate, keep it available through manual translation and suppress its automatic queue offers. |
| **Translation quality** | Have bilingual reviewers score at least 20 examples per pilot customer language, with both incoming messages and outbound drafts. Include error codes, refund or SLA wording, numeric values, and Hong Kong terminology. Require at least 90% usable with minor or no edits, zero critical meaning errors, and full preservation of protected values. Require a Hong Kong reviewer before enabling written Cantonese. |
| **Speed and cost** | Under a sandbox run of 60 uncached translations, target p95 acknowledgement below one second and p95 preview below eight seconds for input up to 1,000 characters. Track timeouts and failures separately. Verify zero provider calls for background events. Test that concurrent requests respect the application budget. These are pilot targets. |
| **Release and recovery** | Save the manifest, migration and restore evidence, sandbox screenshots, evaluator results, and the kill-switch drill. Support reviews the private preview and the customer-visible post before the pilot. On rollback, disable provider calls and sends first, then stop the service. Restore settings only after checking schema compatibility, and invalidate old send confirmations on restart. |

## Assumptions and handoff

- The pilot uses one X3M Slack installation and an X3M-approved commercial Anthropic API account. Live workspace permissions, the Claude model, customer data approval, and Slack Connect behavior are gates to verify during implementation.
- The first implementation handoff records this plan in `PLAN.md`, then delivers the four increments in order. Each increment closes with reproducible evidence before the next begins.
- **Experience First** drove the private queue and reviewable outbound preview. **Make Operations Idempotent** drove event deduplication and the durable send receipt. **Sequence Work into Verifiable Units** put the live Slack Connect and Claude checks ahead of the queue, quality controls, and rollout.
